# v0.4.0 开发验证

2026-11-15。本文记录 v0.4.0 的本地实现与验证；正式发布状态以 GitHub Releases 页面为准。

## 本次范围

- 详情页可“加入想看”，侧边栏“收藏”可打开或移除。与播放历史独立，收藏先写入本机文件再更新显示；写入失败不会显示为已保存，损坏的收藏文件不会被新收藏覆盖。
- 收藏优先重新读取仍已导入的原站点；站点或影片失效时搜索当前片库。移除或更换片源不会删除收藏，也不会重新访问已经移除的配置。
- 保存音量、点播播速和自动下一集开关；直播保持 1×，切回点播恢复所选倍速。
- 点播解析失败或连续等待画面／缓冲停滞 30 秒时，可手动重试或换线路；有其他来源时可换来源。重试保留失败的分集和进度，包括尚未完成的异步续播跳转。
- 代理为上游响应和每次读取设置 30 秒超时；不限制持续传输的总时长。

## 已执行

- `go test ./...`：通过。
- `go vet ./...`：通过。
- `go test -race ./cmd/xiaomu ./internal/proxy`：通过。
- 新增回归覆盖收藏保存、重启、移除、来源失效后的搜索、加载取消和写入失败；偏好恢复及直播倍速隔离；解析／打开失败后的重试、换线路和续播；代理响应／读取超时、请求取消及持续传输。
- 用界面测试器检查了 640 与 1120 像素宽的收藏页和详情页。
- 本机 Apple Silicon 上，原生 AVPlayer 验证 HLS 连续画面、时间推进和分片请求头。
- 原生点播验证：无响应媒体约 30 秒后进入恢复流程；切换到 H.264 和 HEVC 后，均解码出变化的 160×90 画面，从第 4 秒续播并推进到第 5 秒以后，保留 1.5×、音量 0.2 及 Referer／UA。测试媒体在仓库外本地生成，不使用用户片源。

## 可复现的原生点播检查

需要本机已安装 FFmpeg。生成文件只放在仓库外：

```sh
mkdir -p /tmp/xiaomu-vod-fixture
ffmpeg -f lavfi -i testsrc2=size=160x90:rate=10 -t 12 -an -c:v libx264 -threads 1 -pix_fmt yuv420p -g 10 -movflags +faststart /tmp/xiaomu-vod-fixture/h264.mp4
ffmpeg -f lavfi -i testsrc2=size=160x90:rate=10 -t 12 -an -c:v libx265 -threads 1 -x265-params log-level=error:pools=1 -tag:v hvc1 -pix_fmt yuv420p -movflags +faststart /tmp/xiaomu-vod-fixture/hevc.mp4
XIAOMU_NATIVE_MEDIA_DIR=/tmp/xiaomu-vod-fixture go test ./cmd/xiaomu -run '^TestNativeVODRecoveryAndPreferences$' -v -count=1 -timeout=75s
```

HLS 的生成和检查命令见 README。普通测试会跳过需要本机媒体环境的原生检查。

## 剩余限制

- 当前钉扎的 MyGo 在首次读取媒体轨道信息时可能同步等待，导致界面暂停响应。代理已将无上游响应的单次等待限制在 30 秒，但尚未消除这段界面阻塞。修复时没有改 MyGo 版本或技术栈。
- 原生测试使用短时、无音轨的本地视频；实际音频听感、长时间播放、系统睡眠唤醒、Intel Mac 及各种外部片源仍需实机验证。
- 收藏是本机“想看”列表，不包含云同步或自动追更通知。

打包时仅将 `mygo.json` 的版本更新为 `0.4.0`，保留入口、更新公钥和 macOS 要求。没有安装或覆盖用户 App，也没有发布正式在线更新。
